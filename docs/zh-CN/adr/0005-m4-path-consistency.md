# ADR-0005 — M4：路径一致性校验——符号路径条件 vs 回放决策

日期：2026-10-23　　状态：已接受（执行押后；分层 2026-10-21 随 branchTrace
重定形裁决，范围 2026-10-23 划定——`.kquery` 路线自 M3 移入）

English version is authoritative. English see
[en/adr/0005-m4-path-consistency.md](../../en/adr/0005-m4-path-consistency.md)。

## 背景

M3（ADR-0004）按**程序性质**缩小 trace——哪些分支在 `.ll` 里是符号的。这
回答了"这个分支*可能是* fork"，没有回答回放的决策是否**与 KLEE 实际建立的
路径一致**。后者是**执行事实**，由 KLEE 自己记录：每条被探索的路径落一个
公开 **KQuery** 格式的路径条件公式（`.kquery`）。

三条既有裁决约束本层：

1. **分层模型**（2026-10-23）：M1+M2 记录回放 → M3 经 IR 缩小 → M4 符号↔
   实际完整校验。前层是后层的必要条件；后层可选。M4 以 M3 缩小后的决策序列
   为输入形状。
2. **薄桥定位**（2026-10-21，用户裁"方案 A"）：一致性校验器=独立工具，消费
   branchTrace 报告——KLEE 路径约束经**公开 `.kquery` 格式**消费；若 SMT 求
   解会破薄桥/零依赖定位，则按 ptrfuzz 模型拆为独立库依赖项目（撞到即裁）。
3. **E2 代数预铺**（2026-10-21）：`replay/branches.py` 的 `match_path`/
   `equal` 逐元素比对（observed, target）站点列表；**未接回放路径**，在此等
   首个消费点。

## 裁决

1. **M4 = 独立校验工具**（薄桥）。输入：M3 缩小后的 branchTrace 报告+同一
   ktest 的 `.kquery`+ktest 本身。不属于 DAP 服务器运行时面。
2. **`.kquery` 只经公开格式消费**（自写解析器）。**SMT 求解默认不在范围内**：
   无求解器的结构/可解析事实检查（约束计数、逐决策对应、变量/对象绑定）直接
   跑；任何需要真求解的（新输入、蕴含证明）按裁决 2 触发 ptrfuzz 模型拆分。
3. **校验结论**覆盖：每个回放 fork 决策在 KLEE 侧有对应约束（无未解释
   fork）、约束序列与回放顺序一致、不一致以值报告不抛异常（Expect 代数
   家法）。
4. **E2 `match_path`/`equal` 在此成为首个消费点**——接入本工具，不接回放
   路径（2026-10-21 裁决维持）。
5. **执行押后至 M3 落地**。产出 `.kquery` 需要在链路外跑 KLEE（安装是工具链
   事务，非 symrepl 依赖）；产物经公开格式进入。
6. **决策走向（taken/not-taken）**：M3 v1 不落；若公式级对应需要，走向推断
   （native pc 单调性）在该时点落进 M3 注记（撞到即裁）。

## 后果

- 保真度声明——*"回放沿 KLEE 采样的路径"*——变为**可检查**而非断言：对论文
  （§7 artifact），防御故事从"一个回放调试器"升格为"路径保真度可验证的回放
  调试器"。
- 两层互证：M3 陈述程序性质（静态），M4 检查执行事实（动态）——多网交叉
  家法同构。
- 默认深度下零依赖保持；求解器逃生口已预先定价（ptrfuzz 模型），不静默长出
  依赖。
- 工具可选且离线：从不调用它的会话与 ADR-0004 留下的行为完全一致。
