# ADR-0002 — M1 输入契约冻结：单 `.ktest` + 动态分支追踪

日期：2026-10-03　　状态：已接受

## 背景

[roadmap](../roadmap.md) 的待决问题阻塞了 M1 实现：路径条件有多少能仅从
`.ktest` 恢复，多少需要 KLEE 额外产出 sidecar 决策日志？对照 klee/klee
master 源码与文档的调研结论：

- `.ktest`（v2/v3）只含每个符号对象的 `{名字, 字节数, 具体字节}` 与 argv
  元数据，不含任何路径/分支决策。v2 与 v3 布局完全相同（v3 仅把 magic
  `BOUT\n` 改为 `KTEST`），解析器单一代码路径即可。
- KLEE 现有产物中没有任何能把决策映射到分支位置的：`.kquery`/`.cvc`/`.smt2`
  只有逻辑约束、无代码位置，且单侧求解的分支不产生约束；
  `.path`/`.sym.path`（唯一的有序决策日志）官方承认失修，已有"不同路径产出
  相同文件"的已知 bug，且为宿主字节序的内部格式。
- KLEE 官方回放契约是 `-lkleeRuntest` 运行时：按对象顺序向
  `klee_make_symbolic` 注入字节并校验名字/大小（`KTEST_FILE` 环境变量），
  这正是教程给出的标准回放路径。
- LLDB Python API 具备所需全部原语：`SBLaunchInfo` 注入 argv/环境/stdin
  文件动作；`ReadInstructions` + `DoesBranch()` 枚举条件跳转；按地址设断点，
  脚本回调记录结果并返回 `False` 自动继续。

## 决策

冻结 M1 输入契约为"单 `.ktest` + 动态分支追踪"：

1. **必选输入只有一个 `.ktest`（v2/v3）文件。** 解析器接受 v2/v3，读取时
   容忍 `BOUT\n`（v1），版本 > 3 拒绝——与 KLEE `kTest_fromFile` 语义一致，
   避免对未来 v4 静默误解析。
2. **路径决策经 LLDB 下真实执行的动态分支追踪恢复**：预扫描执行范围内的
   条件跳转（`DoesBranch()` + 按架构的助记符过滤），逐地址设断，脚本回调
   按序记录 PC/助记符/结果。
3. **harness 契约与 KLEE 官方一致**：目标以 `-lkleeRuntest` 链接；symrepl
   经 `SBLaunchInfo` 注入 `KTEST_FILE` 与 argv，可用文件动作提供 stdin；
   启动前按解析器校验 ktest 对象名字/大小（对应 `KLEE_RUN_TEST_ERROR`
   语义）。
4. **`.kquery` 为可选、永不必需的诊断附件**（路径条件的逻辑视图：
   pretty-print/校验）。
5. **拒绝为 M1 引入自定义 sidecar 决策日志。** 若未来确需，按 ADR-0001
   的防火墙在本仓库公开定义格式。
6. **"路径条件感知断点"的 M1 范围**：记录路径上全部条件分支（追踪按
   函数/模块范围限定），报告中区分纯具体分支；被追踪分支与 KLEE fork
   产生的"约束子集"的精确映射**推迟到 M3**（IR/DWARF）。

## 后果

- 与原版 KLEE 开箱即用：ktest 由 `-write-ktests`（默认开启）保证存在，
  用户工作流零改动。
- 完全符合标准格式防火墙（ADR-0001）：唯一消费的输入格式是公开的 `.ktest`。
- M1 局限（诚实记录）：动态追踪是路径决策的超集（含与输入无关的具体分支）；
  大目标的逐地址断点有性能开销，M1 以函数/模块范围限定缓解。
- 副产物：二进制级、真实执行序的决策轨迹，严格优于任何 sidecar 能提供的
  数据；M3 的 IR/DWARF 映射可直接叠加其上。
