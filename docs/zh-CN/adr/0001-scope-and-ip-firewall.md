# ADR-0001 — 范围与 IP 防火墙

日期：2026-09-30　　状态：已接受

## 背景

作者的主业是某工业编译器团队（闭源：自研 MLIR 方言、lowering 管线、配套调试系统）。本仓库是个人开源项目，与主业在**领域**上相关（程序分析/符号执行/调试器），但**不得**与主业的代码、方言、管线知识直接相关。

## 决策

1. **格式防火墙（架构级，永久约束）**：symrepl 只消费公开标准格式——KLEE `.ktest`、LLVM IR/bitcode、DWARF、DAP。公司栈仅作为这些格式的"生产方"存在于仓库边界之外。任何"了解某私有代码库/方言才有意义"的代码不得进入本仓库。
2. **不做符号引擎**：symrepl 是符号执行与交互调试之间的薄桥。KLEE 负责反证搜索，symrepl 负责把反证变成可调试的会话——自动断点、逐步注入、状态导出。
3. **MVP 用 LLDB Python API + 纯 Python**：迭代快、与作者的 DAP/lldb 经验直接复用；性能敏感部分（M3+ 如有需要）再下沉 C++。
4. **License：Apache-2.0 WITH LLVM-exception**，与 LLVM 生态一致。

## 后果

- 仓库从第一行起即无 IP 风险；主业 IP 谈判与本仓库解耦（见个人规划 §5.1 风险 1）。
- 功能受"标准格式"约束：若 KLEE 侧的路径条件无法从标准产物恢复，通过**公开定义的 sidecar 格式**扩展（见 roadmap 的 open question），而不是引入任何私有信息。
- 仓库的成长叙事与作者公开身份线一致：定位违反（symrepl）→ 构造保证（分析框架）→ 机器证明（翻译验证）。
